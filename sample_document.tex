\section{Interpretation of the Title}

The project title, ``Design of a Vehicle Tracking Drone,'' presents a classic mechatronic problem: integrating mechanical flight dynamics with autonomous sensing to follow a moving target. 

\subsection{Problem Deconstruction}
In a literal sense, the title implies a single unmanned aerial vehicle (UAV) equipped with sensors to detect and follow a specific ground vehicle. However, current security challenges in urban environments render single-drone solutions ineffective. Static cameras have blind spots, and large commercial drones (like the DJI Phantom series) rely heavily on GPS. These systems fail in \textbf{GPS-denied environments} such as indoor parking lots, tunnels, or dense urban canyons where satellite signals are occluded.

\subsection{The Swarm Interpretation}
Therefore, our group interprets this design problem not as the creation of a single vehicle, but as the development of a node within a \textbf{Mobile Ad-hoc Network (MANET)}. The solution is a ``Swarm'' of Micro-Class drones. Unlike a single high-end drone, a swarm of expendable, agile units (85mm footprint) can create a dynamic relay chain. This allows the system to track vehicles through narrow alleyways where larger drones cannot fly, utilizing distributed sensing to maintain the ``chain of custody'' even if one drone loses visual contact.

\section{Design Requirements}

Based on the swarm interpretation and the guidelines from \textit{EMT 2433 Handout 02}, the following Product Design Specifications (PDS) were formulated.

\subsection{Performance Constraints}
\begin{itemize}
    \item \textbf{Agility (Thrust-to-Weight):} The propulsion system must achieve a Thrust-to-Weight ratio of $>1.6:1$. A standard fleeing vehicle can accelerate at approximately $0.8g$; the drone must exceed this to close the distance.
    \item \textbf{Endurance:} Each unit must achieve a flight time of at least 4 minutes. While short, the swarm architecture allows for "relay replacement" of drones.
    \item \textbf{Latency:} Video transmission and telemetry latency must be $<50\text{ms}$ to ensure the control loop remains stable.
\end{itemize}

\subsection{Geometric Constraints}
\begin{itemize}
    \item \textbf{Footprint:} The frame diagonal must not exceed 120mm. This size is critical for navigating indoor environments like stairwells or ventilation ducts.
    \item \textbf{Weight:} The All-Up Weight (AUW) must remain under 80g. This classifies the drone as a "Micro" class, exempting it from certain heavy aviation regulations and minimizing kinetic energy in crashes.
\end{itemize}

\subsection{Applicable Standards (Ref: H03)}
To ensure professional compliance, the design adheres to the following standards referenced in the course notes:
\begin{itemize}
    \item \textbf{ISO 12100:} General principles for design - Risk assessment and risk reduction. We applied this by using propeller guards and lightweight materials.
    \item \textbf{ISO 8373:} Vocabulary for service robots.
\end{itemize}

\subsection{Communication Protocol Research}
Research into wireless protocols indicates that standard Wi-Fi introduces high latency ($\approx 100$ms) due to the association/handshake process. In contrast, the \textbf{ESP-NOW} protocol allows for connectionless peer-to-peer communication. Eridani et al. demonstrated that ESP-NOW maintains a latency of $<10$ms and a range of up to 200m line-of-sight, making it superior for real-time swarm control compared to Bluetooth (BLE) or Zigbee.

\subsection{Design Calculations}
To ensure the feasibility of the micro-drone concept, the following sizing calculations were performed:

\subsubsection{A. Total Weight Estimation ($W_{total}$)}
\begin{align*}
W_{frame} & \approx 15 \text{ g} && \text{(PLA+ Structure)} \\
W_{motors} & \approx 20 \text{ g} && \text{(4x 1104 Motors)} \\
W_{electronics} & \approx 8 \text{ g} && \text{(PCB + Camera)} \\
W_{battery} & \approx 30 \text{ g} && \text{(2S 450mAh LiPo)}
\end{align*}
\[
\mathbf{W_{total}} \approx \mathbf{73 \text{ g}} \quad (\approx 0.72 \text{ N})
\]

\subsubsection{B. Thrust Requirement}
For agile tracking, a safety factor of 2 is required:
\begin{equation}
T_{req} = W_{total} \times 2 = 146 \text{ g}
\end{equation}
\begin{equation}
T_{per\_motor} = \frac{146}{4} = 36.5 \text{ g per motor}
\end{equation}

\subsubsection{C. Component Verification}
We selected \textbf{1104 7500KV} motors. At 7.4V (2S) with 2.5-inch props, these produce $\approx 65\text{g}$ thrust each.
\begin{equation}
\text{Total Thrust} = 65 \times 4 = 260 \text{ g}
\end{equation}
\begin{equation}
\text{Ratio} = \frac{260}{73} = \mathbf{3.56 : 1}
\end{equation}
\textit{Conclusion: The design exceeds the agility requirement significantly.}

\section{Mechatronic Modules \& Interaction}

The system is composed of distinct mechatronic modules as defined in \textit{EMT 2433 Handout 01}.

\subsection{Module Breakdown}
\begin{enumerate}
    \item \textbf{Mechanical Module:} The 85mm 3D-printed skeleton that provides structural rigidity. It integrates the mounting points for the motors and the central stack.
    \item \textbf{Actuation Module:} 4x BLDC motors driven by MOSFET bridges (ESCs) to convert electrical energy into thrust.
    \item \textbf{Sensory Module:} MPU-6050 for attitude determination (Gyroscope/Accelerometer) and a nano-camera for visual data.
    \item \textbf{Control Module:} The custom ESP32-C3 PCB which executes the PID stabilization loops.
    \item \textbf{Communication Module:} The ESP-NOW mesh network that allows drone-to-drone data relay.
\end{enumerate}

\section{Software Implementation}
The following C++ firmware code implements the ESP-NOW communication protocol and the PID stabilization loop for the ESP32-C3. This code is flashed to each node in the swarm.

\begin{lstlisting}[language=C++, caption=ESP32-C3 Flight Firmware]
/* * Project: Micro-Swarm Tracker
 * Author: Group 19
 * Device: ESP32-C3-MINI-1
 */

#include <esp_now.h>
#include <WiFi.h>
#include <Wire.h>

// --- MPU6050 Registers ---
const int MPU_ADDR = 0x68;
int16_t AcX, AcY, AcZ, GyX, GyY, GyZ;

// --- PID Control Variables ---
float pid_p_gain_roll = 1.3;
float pid_i_gain_roll = 0.04;
float pid_d_gain_roll = 18.0;
float roll_error, roll_i_mem, roll_setpoint;
float roll_prev_error = 0;

float pid_p_gain_pitch = 1.3;
float pid_i_gain_pitch = 0.04;
float pid_d_gain_pitch = 18.0;
float pitch_error, pitch_i_mem, pitch_setpoint;
float pitch_prev_error = 0;

// --- DSHOT Motor Pins ---
#define MOTOR_1_PIN 0
#define MOTOR_2_PIN 1
#define MOTOR_3_PIN 2
#define MOTOR_4_PIN 3

// --- Telemetry Structure ---
typedef struct struct_message {
    int id; // Drone ID
    int throttle;
    int pitch;
    int roll;
    bool track_active;
} struct_message;

struct_message incomingData;

// --- Setup Function ---
void setup() {
  Serial.begin(115200);
  
  // 1. Initialize I2C for IMU
  Wire.begin(4, 5); // SDA on GPIO4, SCL on GPIO5
  Wire.beginTransmission(MPU_ADDR);
  Wire.write(0x6B); // Power Management Register
  Wire.write(0);    // Wake up MPU6050
  Wire.endTransmission(true);

  // 2. Initialize ESP-NOW
  WiFi.mode(WIFI_STA);
  if (esp_now_init() != ESP_OK) {
    Serial.println("Error initializing ESP-NOW");
    return;
  }
  
  // 3. Register Callback
  esp_now_register_recv_cb(OnDataRecv);
  
  // 4. Initialize Motor Pins
  pinMode(MOTOR_1_PIN, OUTPUT);
  pinMode(MOTOR_2_PIN, OUTPUT);
  pinMode(MOTOR_3_PIN, OUTPUT);
  pinMode(MOTOR_4_PIN, OUTPUT);
}

// --- Main Loop ---
void loop() {
  // Read Accelerometer Data
  Wire.beginTransmission(MPU_ADDR);
  Wire.write(0x3B);
  Wire.endTransmission(false);
  Wire.requestFrom(MPU_ADDR, 14, true);
  
  AcX = Wire.read()<<8|Wire.read();
  AcY = Wire.read()<<8|Wire.read();
  
  // --- PID Calculation (Pitch) ---
  // Calculate Error
  pitch_error = incomingData.pitch - AcX;
  
  // Integral Term
  pitch_i_mem += pid_i_gain_pitch * pitch_error;
  
  // Derivative Term (Simplified)
  float pitch_d = pid_d_gain_pitch * (pitch_error - pitch_prev_error);
  pitch_prev_error = pitch_error;
  
  // Total Output
  float output = (pid_p_gain_pitch * pitch_error) + pitch_i_mem + pitch_d;
  
  // --- Motor Mixing Algorithm ---
  int m1 = incomingData.throttle + output; // Front Left
  int m2 = incomingData.throttle - output; // Front Right
  
  writeMotors(m1, m2, m1, m2);
  
  delay(4); // Run loop at 250Hz
}

void OnDataRecv(const uint8_t * mac, const uint8_t *incomingData, int len) {
  memcpy(&incomingData, incomingData, sizeof(incomingData));
}

\section{Results and Discussion}\label{sec:results}

\subsection{Overview}

This chapter presents the results and current status of work completed during the interim phase of the project. Work completed to date covers two main areas: (1)~circuit design and Proteus simulation to verify the MOSFET solenoid valve driver switching behaviour, and (2)~YOLOv11n model training on the assembled binary coffee berry dataset. Baseline performance measurements against the physical machine and full hardware integration are planned for the next phase.

% ---------------------------------------------------------------
\subsection{Design Rationale}
\label{subsec:obj1results}

The existing sorting machine has three documented limitations: motion blur from a rolling-shutter camera at operational chute speed, high end-to-end pipeline latency from a single-threaded inference pipeline on an older Raspberry Pi platform, and classification inaccuracies at the semi-ripe/ripe boundary in the original four-class model. These limitations motivate the hardware and software improvements described in the following sections. Quantitative baseline measurements will be conducted when the improved physical system is assembled and tested.

\subsection{Sorting Mechanism Improvements}
\label{subsec:obj2results}

Three targeted upgrades were implemented to address the root causes identified in the performance audit:

\begin{enumerate}
  \item \textbf{Camera replacement:} The rolling-shutter Raspberry Pi Camera V2 was
        replaced with the \textbf{Arducam OV9281 Global-Shutter Module} (CSI-2,
        1\,MP, Sony OV9281). Simultaneous pixel exposure eliminates the 12--18\,mm
        per-frame smear that degraded colour classification at operating chute speed.
  \item \textbf{Ejector driver transistor upgrade:} PN2222A BJTs were replaced with
        \textbf{IRLZ44N logic-level MOSFETs}. The MOSFET has no minority-carrier
        storage time, giving sub-20\,ns turn-on versus $\approx$100\,ns + 200--600\,ns
        storage for the BJT. Full drive is achieved direct from the ESP32 3.3\,V GPIO
        with negligible steady-state gate current.
  \item \textbf{ESP32 co-processor:} An ESP32 microcontroller was introduced to handle
        all hard real-time tasks---solenoid pulse timing, motor PWM, relay switching---via
        deterministic hardware timers ($<$5\,\textmu{}s ISR latency), relieving the
        Raspberry Pi Linux scheduler from GPIO-critical paths.
\end{enumerate}

\subsubsection{Procured and Verified Hardware}

The following components have been procured, bench-tested, and verified for compatibility:

\begin{itemize}
  \item Raspberry Pi~4 (4\,GB RAM): upgraded main inference platform.
  \item \textbf{Arducam OV9281 Global-Shutter Camera Module}: replacement imaging sensor.
  \item ESP32 DevKit: real-time actuation controller.
  \item LED ring light: consistent illumination above the detection zone.
  \item 2-channel optocoupler relay module (PC817 + SRD-05VDC): compressor and auxiliary switching.
  \item IRLZ44N MOSFETs (×4), 1N5819 Schottky diodes, 220\,$\Omega$ and 100\,k$\Omega$ resistors.
\end{itemize}

\begin{figure}[H]
  \centering
  \includegraphics[width=0.78\textwidth]{Trigger_OFF.PNG}
  \caption{Proteus oscilloscope: MOSFET turn-OFF --- drain recovers to 12\,V;

  \label{fig:trig_off}

Key results from the waveform analysis:
\begin{itemize}
  \item All four MOSFET channels switched correctly on receipt of \texttt{REJECT:n} commands.
  \item No gate ringing observed; 220\,$\Omega$ series resistor adequately damped parasitic oscillation.
  \item Flyback diode clamped solenoid turn-off spike to +12.5\,V (0.5\,V above rail).
  \item 100\,k$\Omega$ pull-down confirmed zero false firing during ESP32 power-on reset.
\end{itemize}

\subsection{Model Training Results}
\label{subsec:obj3results}

The classification model was built using \textbf{YOLOv11n} (Ultralytics), trained on a 2{,}000-image binary dataset assembled from five publicly available Roboflow datasets (detailed in Section~\ref{subsec:dataset}). The selected inference platform is the \textbf{Raspberry Pi~4 (4\,GB RAM)} \cite{raspberrypi2019}, which provides $\approx$3$\times$ the memory bandwidth of earlier Pi generations, enabling YOLOv11 inference to overlap with the next frame capture.

\subsubsection{Dataset and Class Reduction}

The dataset comprises \textbf{2{,}000 images} drawn from five Roboflow Universe coffee berry datasets \cite{roboflow_ripeness,tabiolo_cherry,roboflow_coffeeapp,roboflow_cherryclassification,robopulse_berry} and annotated with two labels: \texttt{accept}
(fully ripe, deep-red) and \texttt{reject} (all other states: unripe, semi-ripe, overripe, damaged). Consolidating four ambiguous ripeness classes into two well-separated outcomes eliminates the dominant misclassification boundary observed in the reference model.

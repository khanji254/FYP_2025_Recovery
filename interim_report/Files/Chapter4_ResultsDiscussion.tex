\subsubsection{Power Monitoring Simulation}

The ADS1115 power monitoring circuit was simulated in Proteus prior to PCB fabrication to validate the voltage divider network, ADC scaling, and dual chute-detection input topology.

\begin{figure}[H]
\centering
\includegraphics[width=0.85\textwidth]{{images/Battery _Monitoring_Proteus_DesignWhite_background.PNG}}
\caption{Proteus simulation of the ADS1115 battery monitoring circuit: 47~k$\Omega$/10~k$\Omega$ divider, dual chute-detection inputs, and I\textsuperscript{2}C power distribution. Project simulation.}
\label{fig:res_proteus_bms}
\end{figure}

Simulation confirmed that the divider output at 14~V (nominal BMS cap) is 2.456~V, and at 15~V (deployment line transient) is 2.632~V, both well within the ADS1115 ±4.096~V input range and producing distinct digital codes (19650 and 21060 respectively) for reliable state discrimination.

\subsubsection{Fabricated PCB}

\subsection{Preliminary Testing Results}

Literature review and design analysis identified three open empirical gaps that define the experimental programme for this phase: no charge-to-force data for the N4 airframe volume; vibration isolation thresholds for the new avionics holder not previously characterised; and deployment timing predictability under live pyrotechnic conditions unvalidated. The scheduled tests below directly address these gaps.

\subsubsection{Pending Tests --- Scheduled for Next Phase}

The following test campaigns have not yet been executed and are planned once PCB fabrication and avionics assembly are complete:

\begin{itemize}
    \item \textbf{XBee-PRO 900HP range test:} Open-field packet-loss measurement at 0.5, 1, 2, 3, and 5~km with the fabricated PCB and installation antenna.
    \item \textbf{Voltage monitoring calibration:} ADS1115-based divider output compared against precision voltage reference across the 12--16.8~V 4S LiPo operating range.
    \item \textbf{Continuity-detection validation:} End-to-end arm/disarm logic tested with known-resistance igniter stubs simulating GOOD, OPEN, and SHORT states.
    \item \textbf{Full-system pop test:} Crimson powder charge ejection force measurement in the N4 airframe to validate structural load calculations.
\end{itemize}

\subsection{Firmware Development Progress}

\subsubsection{Completed Modules}

The following firmware modules have been developed and tested:

\begin{enumerate}
    \item \textbf{XBee Communication Module:} UART interface, packet formation, transmission at configurable rates (tested up to 10 Hz)
    
    \item \textbf{GPS Module Interface:} NMEA sentence parsing, coordinate extraction, fix status detection
    
    \item \textbf{IMU Interface:} I$^2$C communication with MPU6050, raw acceleration data acquisition
    
    \item \textbf{Barometer Interface:} I$^2$C communication with BMP280, pressure and temperature readings, altitude calculation
    
    \item \textbf{Voltage Monitoring:} ADC reading with moving average filter, voltage conversion, low-battery detection
    
    \item \textbf{Continuity Detection:} Test current generation, voltage measurement, resistance calculation, fault classification
    
    \item \textbf{PWM Control:} Configurable duty cycle ramp profiles, timing control, emergency shutdown
\end{enumerate}

\subsubsection{Integration Status}

Individual modules have been integrated into a unified firmware architecture running on FreeRTOS. System successfully:
\begin{itemize}
    \item Reads all sensors at specified rates
    \item Transmits telemetry packets via XBee at 5 Hz
    \item Reports battery voltage and igniter status
    \item Responds to ground station commands
\end{itemize}

\subsubsection{Remaining Firmware Work}

The following modules require completion:
\begin{itemize}
    \item Flight state machine (Pre-launch, Ascent, Apogee detection, Descent, Landed)
    \item Deployment trigger logic (altitude-based for drogue, altitude-based for main)
    \item Data logging to SD card (backup for telemetry loss)
    \item Ground station software interface
\end{itemize}

\subsection{Challenges Encountered}

\begin{itemize}
    \item XBee modules required XCTU-based configuration; AT-command-only approach was insufficient
    \item ESP32 ADC noise under active WiFi addressed with moving average filter ($N=10$)
    \item Initial nichrome wire gauge incorrect; correct 26~AWG stock sourced and verified
    \item PETG 3D prints exhibited warping; resolved by adjusting bed temperature, nozzle temperature, and print speed
\end{itemize}
